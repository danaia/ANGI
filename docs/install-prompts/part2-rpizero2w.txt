# First boot on Pi Zero 2 W

Keep the private key and private install directory selected during the build.
Explain each physical step and wait for the customer to say Continue.

## Connect the direct link

Use a data cable in the micro-USB port marked USB. For additional power use
PWR IN. Match host adapter MAC 02:79:00:00:00:01, use 10.79.0.1/24 without a
gateway and connect to 10.79.0.2. See docs/pi-zero-2w.md.
Check the route and source address before connecting. If the Pi fails to appear
within two minutes, check the data cable, power and card seating with the customer.

## Verify SSH and open the TUI

Connect as root with the workstation identity and the prepared known_hosts.
Use IdentitiesOnly=yes, StrictHostKeyChecking=yes and the profile's HostKeyAlias
from the first connection onward. If the key differs, stop. Read
/proc/device-tree/model and run agx status --json. Confirm this is the selected
board. Open a workstation terminal with ssh -t ... agx tui.

## Create the administrator and connect to the network

In Profile, let the customer set the hostname and create an administrator.
In Network, let them set the Wi-Fi country, scan and use Connect & save. Use
manual entry for a hidden network. Enter passwords only in the TUI.
Use a 2.4 GHz network on the Zero 2 W.
Keep direct SSH connected. Verify the network address with agx wifi status --json
and test DNS and HTTPS with agx wifi check. If the administrator needs a login
key, install the workstation's selected public key in that account with the
account's ownership and SSH permissions. Preserve any existing keys. Verify the
administrator can reconnect before removing the direct link.

## Open the desktop

Forward a free workstation loopback port to the Pi's 127.0.0.1:5900 using the
trusted SSH connection. Verify an RFB greeting and connect the workstation VNC
viewer to the local port. Have the customer sign in, then check
agx services --json. Show how to reconnect and shut down safely.
